# 2026-09-22 工作日志

## 排查：执行「一键启动」后 As-naming（起名测名）没有启动

### 结论（先说结果）
As-naming 不是「没启动」，而是被 pm2 提前拉起、占住了 8080，导致一键启动脚本的探测逻辑误判为"已在运行"而跳过。

### 证据链
1. **一键启动脚本逻辑**（`C:\Users\Lenovo\WorkBuddy\一键启动.bat`）：
   - 第 3 步起名测名先逐个 curl 探测 3210/8080/8888/4321 的 `/api/health`，
     **任一端口返回 200 就判定 SN=RUNNING，直接跳过 `start` 启动窗口**。
   - 第 0 步会先 `pm2 delete health-app / as-naming` 并 `pm2 save`，本意是清理 pm2 隐藏实例。
2. **当前实测**：8080 上有一个服务，`/api/health` 返回 `{"ok":true,"name":"金声玉振 · 起名测名系统"}`，
   确认是 as-naming（express，server.js），跑在 8080 而非首选 3210。
3. **pm2 里 as-naming 是 online 的**：pid 1840，uptime 15h，created at 2026-09-21T12:47:26Z，
   script path 指向 `C:\Users\Lenovo\WorkBuddy\As-naming\server.js`，exec cwd 就是 As-naming 目录。
   即：**昨天被 pm2 拉起来的那个实例到现在还活着，没被一键启动的第 0 步清掉**。
4. **端口漂移原因**：pm2 的 as-naming 环境变量里 `PORT=3210`，但 3210 没起来；
   server.js 的 listenAt 有 EADDRINUSE 自动顺延逻辑（3210→8080→8888→4321），
   out 日志里依次出现 8888/3210/3000/8080 四条"已启动"记录，说明它启动时 3210 被占（或 pm2 环境里 PORT 污染），最终落在 8080。
5. **pm2 自启入口存在**：计划任务「PM2 Resurrect OpenClaw」（State: Ready）+ 启动目录 `boot-hidden.vbs`。
   pm2 daemon 重启时会从 dump.pm2 resurrect 出 as-naming 和 health-app。
6. **health-app（跑悟）也是同一问题**：pm2 里 restarts 高达 4388 次，error log 是 `EADDRINUSE port 3000`——
   一键启动第 0 步 delete 后，pm2 daemon 可能在脚本 `start` 新窗口之前就把进程 resurrect 回来，两边抢 3000 端口死循环。

### 根因
一键启动脚本用「pm2 delete + 独立 cmd 窗口 start」这套，与本机的 **pm2 开机 resurrect 机制**（计划任务 + boot-hidden.vbs + dump.pm2）互相打架：
delete 之后 daemon 会把进程救回来，且 as-naming 的 PORT 环境变量配置与实际端口不一致（3210→漂到 8080），
最终表现为一键启动"看起来没启动任何 As-naming 窗口，但 8080 上其实跑着一个旧实例"。

### 建议修复方向（待用户确认，未改脚本）
- 方案 A：pm2 里给 as-naming 设死 `PORT=3210` 并重做 dump（`pm2 save`），让 resurrect 出来的就是 3210。
- 方案 B：一键启动脚本第 3 步的探测端口列表改成只认 3210（不要把 8080/8888/4321 都当作"是起名测名"），
  或在启动窗口前先 `pm2 delete as-naming` 后多等几秒再探测。
- 方案 C：二选一——要么全走 pm2 托管（不要 start 独立窗口），要么关掉 pm2 resurrect 自启（删计划任务/启动项 + 清 dump）。

## 修复：跑悟三个用户反馈问题

1. **报告页下拉后"返回历史记录"消失**（`public/style.css` + `public/app.js`）
   - 根因：移动端顶栏窄屏会换行成两行（~110px），而报告页返回栏 `.report-top` 吸顶在 `top:58px`、z-index 40，
     被吸顶顶栏（z-index 50）整条盖住——不是 sticky 失效，是被压在下面。
   - 修法：`show()` 切页时给 body 打 `has-backbar`（仅 report/learn），移动端 CSS 里这两个页面让顶栏
     `position: static` 随页滚、返回栏 `top:0`。其余页面顶栏行为不变。学习园地同样的 bug 一并修了。
2. **移动端边缘滑动直接退出程序**（`public/app.js`）
   - 修法：登录后（移动端）`history.pushState` 压一条哨兵记录，把返回手势变成可拦截的 popstate：
     触发即弹"确定要退出跑悟吗"，取消就压回哨兵留在本页，确认才 `history.back()` 真退出。
     `armBackGuard()` 在 setLogged 调用、`disarmBackGuard()` 在 logout 调用；桌面端不启用（isMobile 判断）。
3. **真水无香：剩余 88 次仍提示次数不足**（`api/index.js`）
   - 根因（已复现）：`/api/diagnose` 的 `if (!user || user.quota<=0)` 把**额度读取失败**（data=null）
     也当成"次数用完"返回 402 need_pay → 前端弹"次数不足"充值框。该用户库里实为 87/88 次、orders 为 0
     （额度是手工充的），今早还有 `terminated` / `连接 Dify 失败：fetch failed` 两条记录，说明网络确实在抖。
   - 修法：读取失败（quotaErr || !user）→ 500"网络异常，请稍后重试（本次未扣除诊断次数）"；
     只有确凿读到 `quota<=0` 才 402。复现脚本 `dev-tests/quota-402-repro.js`（打桩 users 读取失败）：
     修复前 402 need_pay，修复后 500。
   - 排查脚本：`dev-tests/quota-probe.js`（看某用户额度与记录状态）、`dev-tests/quota-probe2.js`（额度流水+复刻 diagnose 读取）。
