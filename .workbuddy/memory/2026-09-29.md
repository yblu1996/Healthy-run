# 2026-09-29 工作日志

## 排查：https://as-naming.cpolar.top 打不开

### 结论（先说结果）
cpolar 隧道本身正常，是**本地 as-naming 服务没启动**导致 502。

### 证据链
1. **公网探测**：
   - `https://as-naming.cpolar.top/api/health` → **502 错误的网关**（隧道在线，但后端无服务）
   - 对照组 `https://healthy-run.cpolar.top/api/health` → **200 `{"ok":true}`**（cpolar 账号/隧道工作正常）
   → 排除 cpolar 侧故障，问题在本地后端。
2. **本地端口**：netstat 只有 3000 在监听（PID 37352 = `node api/index.js`，即跑悟）；
   as-naming 的 3210/8080/8888/4321 **全部无监听**，四个端口 `/api/health` 全连不上。
3. **cpolar 配置**（`~/.cpolar/cpolar.yml`）：As-naming 隧道 `addr: "3210"`、`subdomain: As-naming`、`start_type: enable`，
   配置完好；cpolar 客户端两个进程在跑（PID 4844 起于 9/20，PID 25168 起于 9/27）。
4. **pm2 状态**：本会话首次执行 `pm2 list` 时 daemon 不存在、现场 spawn 了一个新 daemon，列表为空
   → as-naming 没被 pm2 托管，也没被一键启动拉起来（上次 9-22 排查后机器重启过，自启链路没把它带起来）。

### 根因
as-naming 本地服务没跑 → cpolar 的 As-naming 隧道指向 3210 但后端无响应 → 公网 502。
跟 9-22 的"端口漂移到 8080"是同一类问题的延续：启动链路（一键启动/pm2 resurrect）不可靠。

### 修复（待用户确认）
启动 as-naming 即可恢复：`cd C:\Users\Lenovo\WorkBuddy\As-naming && npm start`（或一键启动.bat）。
注意：server.js 端口首选 3210，启动后应确认实际监听 3210，否则还是会 502。
