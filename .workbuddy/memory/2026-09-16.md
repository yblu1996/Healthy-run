- 因此问题在扣子平台侧：该 PAT 账号在 api.coze.cn 上找不到该**已发布**工作流。三种可能（按概率）：①工作流没发布（API 只认已发布版本，最常见）；②ID 复制错了（非工作流 ID）；③工作流建在团队空间而 PAT 是个人令牌，没该空间权限。
- 排查技巧：直接用凭证探一次两个站点，能一次性区分"网络/鉴权问题"还是"工作流不存在"，比看前端报错快。

## 上线排查：分析后提示"报告数据异常"

- 工作流发布后能跑通，但报告页报"报告数据异常，请检查扣子工作流输出格式"。
- 探测发现是**双重序列化**：扣子 `data.data` 解析后是 `{diagnosis_result: "...", recognition: "..."}`，两个值本身还是 JSON 字符串（结束节点变量类型选了 String），前端 `renderReport` 取到字符串就报异常。
- 已在 `lib/coze.js` 加容错：解析后若 recognition / diagnosis_result 仍是字符串则再 JSON.parse 一次。老记录（库里已存成字符串的那条）建议清掉 run_records 重来。
- 另发现一个**更严重的问题**：识图节点完全没看到图片——recognition 返回 `image_type: unclear`、`image_error: "未提供图片"`。但图片 URL 公开可访问（HTTP 200 image/jpeg，桶配对了），所以不是存储问题，而是扣子工作流里识图节点的 images 变量引用方式问题：需在多模态节点的消息里以**图片（image）类型**插入 images，而不是当文本插入 `{{images}}`。这一步只能在扣子后台改，代码改不了。
