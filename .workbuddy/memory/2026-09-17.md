## 健康跑平台：扣子工作流连环排查（第三轮）

- 用户报新错：`分析失败：The input parameters provided to the model are invalid.`
- 写探针做三种参数组合的对照实验（脚本用完即删）：
  1. **images 传数组**（和后端一致）→ 扣子 4000 "The input parameters provided to the model are invalid." ← 就是用户看到的错
  2. **images 传单个字符串** → 工作流**成功执行**（code 0，返回了内容）
  3. **只发 user_text** → 4000 Missing required parameters（证明开始节点仍要求 images 等参数）
- **根因**：开始节点的 `images` 参数类型被改成了 String。用户之前修"图片模型看不到"时，很可能把开始节点的 images 类型从 Array,String 改成了 String，导致后端按数组传参时类型校验不通过。
- 正确配法：开始节点 images 类型必须保持 **Array,String**；识图节点消息里以**图片类型**引用该数组变量，扣子会把数组里每张图都喂给模型。两件事要同时成立。
- 附带发现：单字符串那次虽跑通，但节点 2 的输出是大段模型思考过程而非 JSON，说明"输出格式选 JSON"可能被改掉了或模型未遵守，需一并检查。
- 结论：纯扣子平台侧配置问题，代码无需改。

## 复验：用户说改好了，实际仍未通（第四轮，参数级隔离）

- 用户回"改好了"，复验仍报 4000 `The input parameters provided to the model are invalid.`
- 做了三轮对照（脚本用完即删），关键规律：
  - 五个参数**齐全**时 → 报 "input parameters invalid"（不管是单图、多图、空数组、goal 是 none 还是 half、race_date 是空串还是真日期，全都同一个错）
  - 参数**缺失**时 → 报 "Missing required parameters"（说明五个参数都是必填）
  - `history=null` 或 `race_date=null` → 也算缺失（扣子把 null 当缺参数）
- 推断：开始节点的参数类型/必填配置改出问题了。缺参数报缺参数、齐了报"无效"，说明参数齐了之后**类型校验**这关没过。最可能：某个参数类型被改了（如 images 从 Array 改成 String 或反之），或某个必填参数被标成了数组类型但默认值/类型对不上。
- 想查执行历史定位到具体节点：`GET /v1/workflow/run_history`、`/v1/workflow/get`、`/info`、`/detail`、`/list` 全部 404 不存在——扣子国内版没开放这些查询接口，没法从 API 侧看节点配置。
- 结论仍是扣子后台配置问题。让用户重点检查**开始节点**五个参数的类型与必填：images 必须是 Array,String 且必填；user_text/goal/race_date/history 是 String 且必填（空串可以，null 不行）。另外可用 debug_url（错误响应里有）去扣子后台看那次执行的节点级报错。
